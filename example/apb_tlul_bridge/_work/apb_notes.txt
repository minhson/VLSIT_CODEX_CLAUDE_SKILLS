- Issue D of IHI 0024 covers APB2 (Issue A), APB3 (Issue B: PREADY, PSLVERR), APB4 (Issue C: PPROT, PSTRB) and APB5 (Issue D: PWAKEUP, user signals, parity). "APB4" means the signal set of Issue C; do not use the Issue D additions (PWAKEUP, PAUSER, PWUSER, PRUSER, PBUSER, check signals) for an APB4 interface.
- This issue uses the terms Requester and Completer; older issues say Master and Slave.
- Appendix A: PADDR, PPROT, PENABLE, PWRITE, PSTRB and the active lanes of PWDATA must be valid whenever PSEL is asserted (that is, already in the Setup phase). PREADY must be valid when PSEL and PENABLE are asserted. PRDATA (reads) and PSLVERR must be valid only when PSEL, PENABLE and PREADY are all HIGH.
- Section 3.1: PADDR, PWDATA and the other control signals must be stable until the transfer completes (they stay unchanged while PREADY is LOW).
- Section 3.2: PSTRB must be driven LOW for all bits during a read transfer. PSTRB is optional; a Completer documents which sparse writes it supports.
- Section 3.4: PSLVERR is valid only in the last cycle of a transfer. A read that receives an error can return invalid data, and the Requester might still use it. A write that receives an error might or might not have updated the Completer.
